# AGENTS.md — web

Vite + TypeScript client. It does **no cryptography**: every key operation goes
through the WASM module built from `crates/wasm`, which wraps `crates/core`.

## Rules

- **Never edit `web/pkg/`.** It is generated by `wasm-pack` and git-ignored. The
  source of truth is `crates/wasm`.
- **Never implement crypto in TypeScript.** Add a binding in `crates/wasm` and
  call it from `src/main.ts`.
- Keep the "a malicious host could serve modified JavaScript" caveat visible in
  the UI footer and README.
- Do not persist the raw mnemonic; only the passphrase-encrypted blob + salt go
  to `localStorage`.
- Appearance settings (`encchat.settings.v1`), local peer aliases
  (`encchat.labels.v1`) and the display name (`encchat.nick.v1`) may live in
  `localStorage`. Never put keys, the mnemonic or message plaintext there.
- There is no custom CSS. Arbitrary CSS can exfiltrate with `url()` and spoof the
  UI; if it is ever added, sanitize it and treat imports as untrusted.

## Build and test

From `web/` (Windows: use `npm.cmd`, not `npm`):

```powershell
npm.cmd install
npm.cmd run build:wasm   # required before dev/build after a fresh clone
npm.cmd run build        # tsc --noEmit && vite build
npm.cmd run test:wasm    # protocol-level checks through the real WASM module
npm.cmd run dev          # dev server
```

`pkg/` is not committed, so CI and fresh clones must run `build:wasm` first.

## Map

- `src/main.ts` — transport (WebSocket) + UI only: join, verify MACs, handshake,
  relay/decrypt, nickname and settings wiring. It mirrors the CLI's action loop.
- `src/appearance.ts` — portable appearance types, localStorage, CSS mapping.
- `src/settings-page.ts` — the `#/settings` page and its live preview.
- `src/commands.ts` — slash-command metadata plus pure filter/parse helpers.
- `scripts/build-wasm.mjs` — cross-platform `wasm-pack` wrapper.
- `scripts/smoke-test.mjs` — Node test of the handshake/ratchet/store,
  appearance and nickname flows.
